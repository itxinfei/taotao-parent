## 1. Java 基础类

### Q1：HashMap 底层原理？JDK 1.7 和 1.8 的区别？

**要点**：
- 底层结构：数组 + 链表（1.8 后：数组 + 链表 + 红黑树）
- put 流程：计算 hash → 定位桶 → 链表尾插（1.8）→ 冲突转树（链表长度 ≥ 8 且数组 ≥ 64）
- 扩容：默认容量 16，负载因子 0.75，扩容翻倍并 rehash
- 线程不安全；1.7 头插法并发扩容可能死循环，1.8 尾插法修复

**项目结合**：本项目缓存商品信息到 Redis（key-value 结构），面试时可延伸讲"为什么缓存不用本地 HashMap 而用 Redis"（分布式共享、过期、持久化）。

### Q2：synchronized 和 ReentrantLock 的区别？

| 对比 | synchronized | ReentrantLock |
|------|--------------|---------------|
| 实现 | JVM 层面（Monitor） | JUC 层面（AQS） |
| 锁获取 | 自动 | 手动 lock/unlock |
| 公平锁 | 非公平 | 可公平/非公平 |
| 响应中断 | 不支持 | 支持 lockInterruptibly |
| 条件变量 | wait/notify | Condition（多条件队列） |

**项目结合**：本项目用 Redis `incr` 原子生成订单号，可延伸"为什么不用 synchronized 保证订单号唯一"（分布式下 JVM 锁失效，需分布式锁）。

### Q3：ThreadLocal 的原理与内存泄漏？

- 每个线程持有 ThreadLocalMap，key 是 ThreadLocal 弱引用，value 是强引用
- 内存泄漏：ThreadLocal 被回收后 key=null，但 value 仍被引用 → 用完后必须 `remove()`
- 典型场景：数据库连接、用户上下文、SimpleDateFormat

### Q4：进程和线程的区别？线程池的核心参数？

**线程池 7 大参数**：corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler（拒绝策略）。

**执行流程**：核心线程 → 队列 → 非核心线程 → 拒绝策略。

**项目结合**：search-web 的 `GlobalExceptionResolver` 里用 `new Thread(mailRunnable).start()` 发告警邮件 —— 面试时可以说"实际生产应改为线程池，避免每次异常都新建线程"（体现你有优化意识）。

### Q5：Java 内存模型（JMM）与 volatile？

- JMM：主内存 + 工作内存，volatile 保证可见性与有序性（禁止指令重排），不保证原子性
- happens-before 原则

## 2. Spring / Spring MVC 类

### Q6：Spring IoC 和 AOP 是什么？

- **IoC（控制反转）**：对象创建与依赖关系交给容器管理，解耦
- **AOP（面向切面）**：横切关注点（事务、日志）与业务逻辑分离

**项目结合**：
- IoC：`@Service`/`@Autowired`/`@Resource` 管理 Service、Mapper、JedisClient
- AOP：`applicationContext-trans.xml` 用 `<aop:advisor>` 给 service 包方法加事务

### Q7：Spring Bean 的生命周期？

实例化 → 属性填充 → Aware 回调 → BeanPostProcessor 前置 → init-method → BeanPostProcessor 后置 → 使用 → destroy。

### Q8：Spring 事务的传播行为？为什么默认 REQUIRED？

| 传播行为 | 说明 |
|----------|------|
| REQUIRED（默认） | 有事务则加入，无则新建 |
| REQUIRED_NEW | 无论有无都新建，挂起当前 |
| SUPPORTS | 有则加入，无则非事务执行 |
| NESTED | 嵌套事务（SavePoint） |

**项目结合**：本项目 `createOrder` 插入订单主表+明细+收货，三个写操作在一个事务里，任一失败全部回滚。

### Q9：Spring MVC 的执行流程？

```
DispatcherServlet → HandlerMapping（找Controller）→ HandlerAdapter（执行方法）
→ 返回 ModelAndView → ViewResolver 解析 → 渲染 → 响应
```

**项目结合**：本项目所有 web 模块都是这个流程；`@ResponseBody` 用 Jackson/FastJSON 序列化返回 JSON。

### Q10：Spring 解决循环依赖？

三级缓存：singletonObjects → earlySingletonObjects → singletonFactories（提前暴露半成品对象，AOP 代理在此生成）。默认支持单例 setter 循环依赖。

## 3. MyBatis 类

### Q11：#{} 和 ${} 的区别？

- `#{}`：预编译占位符（PreparedStatement），防 SQL 注入
- `${}`：字符串拼接，有注入风险，仅用于动态表名/排序字段

**项目结合**：本项目 Mapper XML 全部用 `#{}`；`orderByClause` 用 `${}`（由代码内部构造，不来自用户直接输入）。

### Q12：MyBatis 一级缓存和二级缓存？

- 一级缓存：SqlSession 级别，默认开启，同一个 Session 相同查询命中
- 二级缓存：namespace（Mapper）级别，需配置，跨 Session 共享

### Q13：PageHelper 分页原理？

MyBatis 插件（Interceptor）拦截 Executor，自动改写 SQL 加 `LIMIT` 并执行 `COUNT(*)`。

### Q14：MyBatis 如何实现批量插入？

```xml
<insert id="insertBatch" parameterType="list">
  insert into tb_item (title, price) values
  <foreach collection="list" item="item" separator=",">
    (#{item.title}, #{item.price})
  </foreach>
</insert>
```

## 4. 分布式与中间件类

### Q15：Dubbo 和 Spring Cloud 的区别？

| 对比 | Dubbo | Spring Cloud |
|------|-------|--------------|
| 通信 | RPC（高性能、二进制） | REST（HTTP，通用） |
| 注册中心 | ZooKeeper 等 | Eureka/Nacos/Consul |
| 服务治理 | 成熟（路由/容错/限流） | 生态丰富 |
| 语言 | 偏 Java | 多语言友好 |

**项目结合**：本项目用 Dubbo 2.5.3，5 个 Provider + 7 个 Consumer，ZooKeeper 做注册中心。

### Q16：分布式服务如何保证幂等？

**要点**：同一请求重复执行结果一致。
- 方案：唯一键约束（数据库）、Token 机制（下单前领 token）、Redis setnx、状态机
- **项目结合**：本项目订单号用 Redis `incr` 生成，可延伸"如果消费者重复消费 MQ 消息，如何保证不重复建索引"（更新型操作天然幂等；插入型需唯一键）

### Q17：Redis 缓存穿透/击穿/雪崩的区别与解决？

| 问题 | 现象 | 解决 |
|------|------|------|
| 穿透 | 查不存在的数据，打穿缓存到 DB | 缓存空值、布隆过滤器 |
| 击穿 | 热点 key 过期瞬间，大量请求打 DB | 互斥锁、逻辑过期 |
| 雪崩 | 大量 key 同时过期 | 过期时间加随机、多级缓存 |

**项目结合**：本项目商品缓存 `ITEM_INFO:{id}:BASE` + `ITEM_EXPIRE=86400`，更新时主动删缓存。

### Q18：Redis 的持久化方式？

- RDB：定时快照，恢复快、可能丢数据
- AOF：追加日志，数据全、文件大
- 混合持久化（4.0+）

### Q19：消息队列如何保证消息不丢失？

| 环节 | 措施 |
|------|------|
| 生产端 | confirm 确认机制 |
| Broker | 持久化 + 集群主从 |
| 消费端 | 手动 ack，处理成功才确认 |

**项目结合**：本项目 ActiveMQ 的 topic 消息，消费者 `onMessage` 里 try-catch，失败记日志（教学简化版；可延伸讲事务消息、死信队列）。

### Q20：Solr 和 Elasticsearch 的区别？

| 对比 | Solr | ES |
|------|------|-----|
| 性能 | 静态数据好 | 实时搜索好 |
| 易用性 | 配置复杂 | 上手快、REST API |
| 生态 | 老牌 | 生态活跃（ELK） |

### Q21：什么是分布式锁？怎么实现？

- 目的：跨 JVM 互斥
- 实现：Redis `setnx` + 过期时间、Redisson 看门狗、ZooKeeper 临时顺序节点
- **项目结合**：本项目未用分布式锁（Redis incr 原子性天然避免订单号并发问题），可延伸"秒杀场景如何用分布式锁防超卖"

### Q22：ZooKeeper 的节点类型与 Watch 机制？

- 节点类型：持久节点、临时节点、顺序节点、临时顺序节点
- Watch：一次性监听，节点变化通知客户端
- **项目结合**：Dubbo 利用临时节点做服务注册，Provider 宕机 ZK 会话超时自动删除节点

## 5. 数据库与电商业务类

### Q23：MySQL 索引失效的场景？

1. 对索引列使用函数/计算
2. 左模糊 `LIKE '%xx'`
3. 隐式类型转换
4. OR 连接非索引列
5. 不满足最左前缀

**项目结合**：`tb_item` 建了 `cid`、`status`、`updated` 索引，`tb_order` 建了 `create_time`、`status` 索引。

### Q24：订单状态机如何设计？

```
1未付款 → 2已付款 → 3未发货 → 4已发货 → 5交易成功
    ↘            ↘
     6交易关闭（超时/取消）
```

**项目结合**：本项目 `tb_order.status` 六种状态 + Quartz 定时把超时未付款订单置为 6。

### Q25：为什么订单明细要存商品快照？

商品会改价、改名、下架，但已成交订单必须按购买时信息展示/对账。所以 `tb_order_item` 冗余了 title/price/pic_path。

### Q26：数据库和缓存一致性怎么保证？

先写库 → 删缓存（Cache-Aside），允许短时间不一致；要求强一致用分布式锁/事务消息。

### Q27：如何设计一个秒杀系统？（扩展）

1. 前端：按钮置灰、限流
2. 网关/Nginx：限流、黑白名单
3. Redis：预减库存（decr 原子）
4. MQ：削峰，异步创建订单
5. 数据库：乐观锁/唯一索引兜底防超卖

## 6. 项目类综合题

### Q28：请介绍一下你的项目？

**回答框架（STAR 法则）**：
- **背景**：淘淘商城是分布式 B2C 电商，12 个模块，覆盖商品/搜索/购物车/订单/登录
- **职责**：负责商品管理与搜索模块
- **难点**：缓存一致性、异步索引同步、订单号生成
- **成果**：商品上架到搜索可见 < 3 秒；缓存命中率显著提升

### Q29：项目里最有挑战的事？

**推荐素材**：
- 商品缓存穿透/一致性问题的解决
- 上架商品"搜索不到"—— 排查出是 MQ 未消费导致索引没同步
- 订单号生成从数据库自增改为 Redis incr，解决分布式唯一

### Q30：如果用户量翻 10 倍，你的项目哪里先扛不住？

1. 数据库：单库单表 → 分库分表（Sharding-JDBC/MyCat）
2. Redis：单机 → 集群/哨兵
3. 静态页：Nginx + CDN
4. 消息堆积：多消费者、队列分区

## 7. 面试答题技巧

1. **先结论后展开**：先说"是/不是/用什么"，再讲原理
2. **结合项目**：每题尽量落到"我在项目里怎么用的"
3. **主动挖坑**：讲到缓存一致性时主动说"我们还有优化空间（如双删、延迟双删）"
4. **STAR 法则**讲项目：情境-任务-行动-结果
5. **不会的题**：诚实说不会，但给出思路方向
