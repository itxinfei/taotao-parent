# 05 二次开发指南与常见问题

> 学习目标：掌握在淘淘商城上"加功能、改功能"的完整套路，以及开发部署中的高频问题排查方法。

## 1. 二次开发总览

### 1.1 在哪个模块加代码？

先定位功能属于哪一层：

| 你要改什么 | 改哪个模块 |
|-----------|-----------|
| 数据库表 / SQL | `taotao-manager-dao`（Mapper）或对应 service 的 dao |
| 业务逻辑 | 对应业务模块的 `*-service`（如商品→manager-service） |
| 后台管理页面 | `taotao-manager-web` |
| 门户/用户页面 | `taotao-portal-web` / `search-web` / `item-web` 等 |
| 登录相关 | `taotao-sso`（接口+实现）、`sso-web`（页面） |
| 公共工具/返回对象 | `taotao-common` |

> 核心原则：**先找到对应的 service 模块改接口和实现，再改 web 模块调用**。

### 1.2 一次完整的新功能开发流程（以"商品评价"为例）

**步骤 1：建表（MySQL）**

```sql
CREATE TABLE tb_item_comment (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  item_id BIGINT NOT NULL COMMENT '商品ID',
  user_id BIGINT NOT NULL COMMENT '用户ID',
  content VARCHAR(500) COMMENT '评价内容',
  score TINYINT COMMENT '评分1-5',
  created DATETIME COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

**步骤 2：生成 Mapper 与 POJO**

方式一：用 MyBatis Generator（推荐，项目 POJO 都是它生成的）
方式二：手写（对照已有 `TbItem.java` / `TbItemMapper.java` / `TbItemMapper.xml` 照葫芦画瓢）

```java
// TbItemComment.java（放在 taotao-manager-pojo）
public class TbItemComment implements Serializable {
    private Long id;
    private Long itemId;
    private Long userId;
    private String content;
    private Byte score;
    private Date created;
    // getter/setter...
}
```

**步骤 3：定义 Dubbo 接口（taotao-manager-interface）**

```java
public interface ItemCommentService {
    TaotaoResult addComment(TbItemComment comment);          // 发表评价
    TaotaoResult getCommentsByItemId(Long itemId, int page, int rows);  // 分页查询
}
```

**步骤 4：实现服务（taotao-manager-service）**

```java
@Service
public class ItemCommentServiceImpl implements ItemCommentService {

    @Autowired
    private TbItemCommentMapper itemCommentMapper;

    @Override
    public TaotaoResult addComment(TbItemComment comment) {
        comment.setCreated(new Date());
        itemCommentMapper.insert(comment);
        return TaotaoResult.ok();
    }

    @Override
    public TaotaoResult getCommentsByItemId(Long itemId, int page, int rows) {
        PageHelper.startPage(page, rows);
        TbItemCommentExample example = new TbItemCommentExample();
        example.createCriteria().andItemIdEqualTo(itemId);
        List<TbItemComment> list = itemCommentMapper.selectByExample(example);
        return TaotaoResult.ok(list);
    }
}
```

**步骤 5：发布 Dubbo 服务（applicationContext-service.xml）**

```xml
<dubbo:service interface="com.taotao.service.ItemCommentService"
               ref="itemCommentServiceImpl" timeout="30000"/>
```

**步骤 6：Web 模块引用（item-web 的 springmvc.xml）**

```xml
<dubbo:reference interface="com.taotao.service.ItemCommentService" id="itemCommentService"/>
```

**步骤 7：Controller 调用（item-web）**

```java
@Controller
public class CommentController {
    @Resource
    private ItemCommentService itemCommentService;

    @RequestMapping("/item/comment/{itemId}")
    @ResponseBody
    public TaotaoResult listComments(@PathVariable Long itemId,
                                     @RequestParam(defaultValue="1") Integer page,
                                     @RequestParam(defaultValue="10") Integer rows) {
        return itemCommentService.getCommentsByItemId(itemId, page, rows);
    }
}
```

**步骤 8：JSP 页面展示**

在 `item.jsp` 详情页下方加评价列表区域，用 JSTL 遍历 `commentList`。

**步骤 9：验证**

- 重新编译：`mvn clean install -DskipTests`
- 重启 manager-service 与 item-web
- 调接口验证数据落库、分页正确

### 1.3 改造现有功能的套路

| 场景 | 改法 |
|------|------|
| 改查询条件 | 改 Service 的 Example 条件 + Mapper XML |
| 改返回字段 | 改 POJO + Mapper XML 的 resultMap / SQL |
| 加缓存 | 参照 `getItemById` 的"先查缓存→查库→回填"三段式 |
| 加异步处理 | 发 MQ 消息 + 写监听器（参照 ItemAddMessageListener） |
| 加页面 | web 模块加 Controller 方法 + JSP |

## 2. 代码规范与约定

### 2.1 命名约定

| 类型 | 约定 | 示例 |
|------|------|------|
| 数据库表 | `tb_` 前缀 | tb_item |
| POJO | `Tb` 前缀 | TbItem |
| Mapper | `TbXxxMapper` | TbItemMapper |
| Service 接口 | `XxxService` | ItemService |
| Service 实现 | `XxxServiceImpl` | ItemServiceImpl |
| Controller | `XxxController` | ItemController |
| 事务方法 | `insert*/update*/delete*/create*` 前缀 | createItem、updateItem |

### 2.2 编码规范

- 保持 JDK 1.7 兼容（不要用 lambda、`Map.getOrDefault` 等 Java 8+ API）
- 日志用 SLF4J：`private static final Logger logger = LoggerFactory.getLogger(Xxx.class)`
- 禁止 `System.out.println` / `e.printStackTrace()`
- 返回统一用 `TaotaoResult`（status=200 成功）
- Redis 操作必须 try-catch 容错，异常不影响主流程

### 2.3 事务注意事项

- 写操作（insert/update/delete/create 开头的方法）自动纳入事务
- 事务只对 `com.taotao.service` 包下方法生效（AOP 切面范围）
- **同类内 this 调用不走事务代理**：`A` 方法调同类 `B` 方法，B 的事务注解/切面不生效

## 3. 常见问题 FAQ

### 3.1 编译期问题

**Q1：mvn 编译报错找不到符号 / 依赖下载失败**
```bash
# 清本地缓存强制更新
mvn clean install -U -DskipTests
# 检查是否先安装了父 POM
mvn install -N
```

**Q2：修改了 service 接口，Web 模块还是旧接口**
各模块是独立进程，接口改动后必须**全部重新编译安装**并重启：
```bash
mvn clean install -DskipTests   # 全量重装
```

**Q3：编码问题（编译时中文乱码）**
pom 已配置 UTF-8；IDE 里把 File Encoding 设为 UTF-8。

### 3.2 启动期问题

**Q4：Web 模块启动报 `No provider available for ... ItemService`**

原因：对应 service 未启动，或注册中心地址不对。

排查：
```bash
# 1. 确认 service 启动日志有 "Register dubbo service succeeded"
# 2. 确认 ZooKeeper 上能看到服务
zkCli.sh -server localhost:2181
ls /dubbo/com.taotao.service.ItemService/providers
# 3. 确认 web 的 dubbo:registry 地址与 service 一致
```

**Q5：启动报端口被占用**
```bash
netstat -ano | findstr :8081   # Windows
netstat -tlnp | grep 8081       # Linux
# 找到 PID 后 kill
```

**Q6：`Failed to connect to zookeeper`**
ZooKeeper 未启动或地址不通：
```bash
zkServer.sh start
telnet localhost 2181
```

### 3.3 运行期问题

**Q7：后台新增商品成功，但搜索搜不到**

原因：ActiveMQ 未启动或索引未同步。

排查：
```bash
# 1. 确认 ActiveMQ 已启动
# 2. 到 Solr 查是否新增
curl "http://localhost:8983/solr/collection1/select?q=*:*&rows=1"
# 3. 没有 → 重新全量导入索引（后台"索引库管理"）
```

**Q8：商品详情页图片显示不出来**

排查链：
1. FastDFS 是否启动：`fdfs_monitor /etc/fdfs/client.conf`
2. client.conf 的 tracker_server 地址是否正确
3. IMAGE_SERVER_URL 是否能访问（浏览器直接打开 URL）
4. 是否上传成功（后台看返回的 error 字段）

**Q9：登录后跳回首页还是未登录状态**

排查链：
1. sso-service 是否启动、Redis 是否有 `USER_SESSION:*` 键
2. Cookie 是否写入（浏览器 F12 → Application → Cookies 看 TT_TOKEN）
3. 各 web 模块 `TOKEN_KEY` 是否一致（都应为 TT_TOKEN）
4. 域名问题：Cookie 的 domain 配置是否覆盖所有子系统

**Q10：下单失败 / 订单号异常**

原因多为 Redis 不可用（订单号靠 Redis incr）：
```bash
redis-cli ping                # 应返回 PONG
redis-cli get ORDER_ID_GEN_KEY
```

**Q11：后台管理 EasyUI 表格加载不出数据**

排查：
1. 接口是否返回正确 JSON（浏览器访问 `/item/list?page=1&rows=30`）
2. 返回格式是否符合 EasyUI：`{"total":N,"rows":[...]}`
3. 数据库是否有数据

**Q12：修改了代码，页面没变化**

- 确认重新编译并重启了对应模块
- JSP 修改：如果是独立 Tomcat，清理 Tomcat work 目录缓存
- 浏览器强刷（Ctrl+F5）

### 3.4 性能问题

**Q13：商品详情慢**

排查：
1. Redis 是否生效（`redis-cli keys "ITEM_INFO*"` 看有没有缓存）
2. 首次访问慢是正常的（缓存未命中查库+回填）
3. 大量请求打库 → 检查缓存过期时间是否过短

**Q14：搜索慢**

1. Solr 索引是否太大未优化：`curl "http://localhost:8983/solr/collection1/update?optimize=true"`
2. 查询条件是否合理（分页、过滤）

## 4. 调试技巧

### 4.1 日志调试

```java
logger.info("参数: itemId={}, page={}", itemId, page);   // 占位符方式
logger.error("出错", e);                                    // 异常带堆栈
```

日志位置：`${catalina.home}/logs/taotao-xxx.log`，错误在 `*-error.log`。

### 4.2 远程调试

以 manager-web 为例：

```bash
# Tomcat 启动参数加调试端口
JPDA_ADDRESS=5005 mvn tomcat7:run
# 或独立 Tomcat：catalina.sh jpda start

# IDE 中配置 Remote 调试连接 localhost:5005
```

### 4.3 常用排查命令速查

```bash
# Redis
redis-cli keys "*" | head
redis-cli monitor            # 实时观察所有命令

# ZooKeeper
zkCli.sh -server localhost:2181
ls /dubbo

# Solr
curl "http://localhost:8983/solr/collection1/select?q=*:*&rows=10"

# ActiveMQ
# 管理台 http://localhost:8161 查看队列/主题消息数

# MySQL
mysql -uroot -p taotao -e "show processlist;"   # 看当前 SQL
mysql -uroot -p taotao -e "select * from tb_item limit 5;"
```

### 4.4 给代码加断点的最佳位置

| 想观察什么 | 断点位置 |
|-----------|----------|
| 请求参数 | Controller 方法第一行 |
| 业务逻辑 | ServiceImpl 方法内 |
| SQL 执行 | Mapper XML 对应方法调用处（或开 Druid 日志） |
| 缓存命中 | getItemById 的 if 判断处 |
| 消息收发 | JmsTemplate.send / Listener.onMessage |

按难度递进，建议动手完成：
